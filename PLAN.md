# Yara Web Search API — Implementation Plan

## Context
Building a Tavily-like web search API called "yara" from scratch. The project directory is empty. Phase 1 uses SearXNG (self-hosted metasearch) + Jina Reader for content extraction. Phase 2 adds a true independent index using Crawlee + Convex (replaces PostgreSQL) + Meilisearch. Stack is kept lean: native `fetch` instead of axios, custom concurrency limiter instead of p-limit, Node 20's `--env-file` flag instead of dotenv.

---

## Tech Stack — Lean Choices

| Concern | Choice | Replaces |
|---|---|---|
| HTTP client | Native `fetch` (Node 20 built-in) | axios |
| Env vars | `node --env-file=.env` flag | dotenv |
| Concurrency limit | ~15-line custom `pLimit` helper | p-limit package |
| Crawler storage | **Convex** (cloud DB + built-in full-text search) | PostgreSQL |
| Search index | **Meilisearch** (self-hosted Docker) | — |
| Logger | Pino (lightweight, keep) | — |
| HTML parsing | Cheerio + @mozilla/readability + jsdom | — |
| Rate limiting | express-rate-limit + rate-limit-redis | — |
| Cache | ioredis + Redis (Docker) | — |

---

## Why Convex Instead of PostgreSQL?
- No SQL schema migrations — documents just need a TypeScript schema file
- Built-in upsert pattern (query → patch or insert in one mutation)
- **Built-in full-text search** (Tantivy/BM25) — could skip Meilisearch for basic search
- Has a free tier (0.5 GB, enough for dev + small prod)
- `ConvexHttpClient` works perfectly from Express (no Next.js needed)
- For self-hosted preference: Convex has a Docker self-host option
- Meilisearch is kept for production-grade ranking control (Phase 2 can use either)

## Custom `pLimit` (replaces the npm package)

```typescript
// src/utils/pLimit.ts
export function pLimit(concurrency: number) {
  let active = 0;
  const queue: Array<() => void> = [];

  const next = () => {
    if (active < concurrency && queue.length > 0) {
      active++;
      queue.shift()!();
    }
  };

  return function limit<T>(fn: () => Promise<T>): Promise<T> {
    return new Promise((resolve, reject) => {
      queue.push(() => {
        fn()
          .then(resolve)
          .catch(reject)
          .finally(() => { active--; next(); });
      });
      next();
    });
  };
}
```

## Native `fetch` Pattern (replaces axios)

```typescript
// searxng.ts example
const params = new URLSearchParams({ q: query, format: "json" });
const res = await fetch(`${config.searxng.baseUrl}/search?${params}`, {
  signal: AbortSignal.timeout(10_000),
});
if (!res.ok) throw new Error(`SearXNG error: ${res.status}`);
const data = await res.json() as SearXNGResponse;
```

Same pattern for Jina Reader, content fetch for Readability/Cheerio.

## Phase 1 Implementation Order

1. **Bootstrap** — `npm init`, install deps (see packages below), `tsconfig.json`, `.env`, `.gitignore`
2. **`src/utils/pLimit.ts`** — custom concurrency limiter (no npm package)
3. **`src/utils/logger.ts`** — Pino
4. **`src/config/index.ts`** — reads `process.env`, validates required vars, exports typed `AppConfig`
5. **`src/services/cache.ts`** — ioredis singleton, `getCache`, `setCache`, `buildSearchCacheKey` (SHA-256 via `crypto`)
6. **`searxng/settings.yml`** — enable `json` under `formats:` (CRITICAL — without this, API returns 403)
7. **`docker-compose.yml`** — SearXNG + Redis + API on `yara_net`
8. **`src/services/searxng.ts`** — native `fetch` to SearXNG, maps to `SearchResult[]`
9. **`src/services/contentExtractor.ts`** — Jina (fetch) → Readability+JSDOM → Cheerio fallback, never throws
10. **`src/services/searchOrchestrator.ts`** — cache check → SearXNG → parallel extraction (custom pLimit) → cache write
11. **`src/middleware/rateLimiter.ts`** — `express-rate-limit` + `rate-limit-redis`
12. **`src/routes/health.ts`** + **`src/routes/search.ts`**
13. **`src/app.ts`** + **`src/index.ts`**

**Phase 1 packages** (lean list):
```

@mozilla/readability jsdom cheerio pino pino-pretty

```
Dev: `typescript @types/express @types/node @types/jsdom ts-node-dev`

## Phase 2 Implementation Order

14. **`convex/schema.ts`** — define `pages` table: `url, domain, title, content, contentHash, crawledAt, indexed, indexedAt`
15. **Run `npx convex dev`** — generates `convex/_generated/` type-safe API
16. **`convex/pages.ts`** — mutations: `upsertPage`, `markIndexed`; queries: `getUnindexedPages`, `searchPages`
17. **`src/services/phase2/convexClient.ts`** — `ConvexHttpClient` singleton using `CONVEX_URL` env var
18. **`docker-compose.phase2.yml`** — Meilisearch service
19. **`src/services/phase2/indexer.ts`** — Meilisearch client, `ensureIndex`, `indexPages`, `searchIndex`
20. **`src/services/phase2/crawler.ts`** — Crawlee `CheerioCrawler`, same-domain links, depth limiting, upserts to Convex
21. **`src/services/phase2/hybridSearch.ts`** — parallel `searchIndex` + `searchSearXNG`, dedup, own results first
22. **`src/routes/crawl.ts`** — `POST /api/crawl`, responds 202, runs crawl in background
23. **Wire into `app.ts`** — register crawl route; swap orchestrator to use `hybridSearch`

## Convex Schema (`convex/schema.ts`)

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  pages: defineTable({
    url: v.string(),
    domain: v.string(),
    title: v.optional(v.string()),
    content: v.string(),
    contentHash: v.string(),
    crawledAt: v.number(),          // Unix ms timestamp
    indexed: v.boolean(),
    indexedAt: v.optional(v.number()),
  })
    .index("by_url", ["url"])
    .index("by_domain", ["domain"])
    .index("by_indexed", ["indexed"])
    .searchIndex("search_content", {
      searchField: "content",
      filterFields: ["domain"],
    }),
});
```

## Critical Pitfalls

- **SearXNG 403**: `searxng/settings.yml` must exist on disk with `json` under `search.formats` BEFORE `docker compose up`
- **Convex codegen**: Must run `npx convex dev` after editing `convex/schema.ts` to regenerate `_generated/` types
- **Crawlee disk storage**: Call `Configuration.getGlobalConfig().set("persistStorage", false)` to avoid `./storage/` disk fill inside the API process
- **JSDOM memory**: Cap fetch response body at 2MB before passing to JSDOM
- **Node 20 `--env-file`**: Only works in Node 20.6+. Confirm version with `node --version`
- **Convex free tier storage**: 0.5 GB — upgrade to Starter plan for production crawls
