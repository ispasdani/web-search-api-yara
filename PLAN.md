# Yara Web Search API — Implementation Plan

## Context
Building a from-scratch web search engine with zero external search/content APIs. The user wants raw search results with advanced filtering, Convex for storage (approved), and no auth for now. Goal is the leanest possible implementation of the core search loop: crawl → index → query.

**Removed:** SearXNG, Jina Reader, Express server, Meilisearch, Redis, Docker. Convex replaces all of them — it hosts the HTTP search endpoint, the database, and the full-text search index. The only local piece is the crawler script.

**Phase 1** — Core: Convex search API (httpAction) + Convex DB (pages table + searchIndex) + local Node.js crawler.
**Phase 2** — Ranking improvements + scheduled re-crawling + Playwright for JS-heavy sites.

---

## Tech Stack

| Concern | Choice | Why |
|---|---|---|
| Search API host | **Convex httpAction** | Zero server infra, hosts HTTP endpoint for free |
| Database + search index | **Convex DB** (built-in BM25/Tantivy full-text search) | Replaces Meilisearch + SQLite + Redis |
| HTTP client | Native `fetch` (Node 20) | No axios dep |
| Env vars | `node --env-file=.env` flag | No dotenv dep |
| Concurrency | Custom 15-line `pLimit` util | No p-limit dep |
| Crawler | **Crawlee** `CheerioCrawler` | Queue, rate limit, robots.txt built-in |
| HTML parsing | **Cheerio** + **@mozilla/readability** + **jsdom** | Self-hosted extraction, no API |
| Language detect | **franc** (npm, offline, 176 langs) | No external API |
| Logger | **Pino** | Lightweight |
| Phase 2 (JS sites) | **Playwright** + `PlaywrightCrawler` | Headless Chromium, self-hosted |

**No Docker. No Express. No Redis. No Meilisearch. No auth.**

## How It All Works

```
Local crawler script (src/crawler.ts)
    │
    │  reads seeds/urls.txt
    │  Crawlee CheerioCrawler fetches each page
    │  extractor.ts → clean text (Cheerio + Readability)
    │  franc → lang, classify.ts → contentType
    │
    ▼
ConvexHttpClient.mutation(api.pages.upsertPage, { url, domain, title,
    content, snippet, lang, contentType, crawledAt })
    │
    ▼
Convex DB — pages table (with full-text searchIndex on content)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

User query:
GET https://<deployment>.convex.site/search?q=nodejs&site=nodejs.org&lang=en
    │
    ▼
convex/http.ts  httpAction
    │  parse query params → build search filter
    │
    ▼
ctx.runQuery(api.pages.searchPages, { q, domain, lang, contentType,
    after, before, sort, page, limit })
    │
    ▼
Convex full-text search (BM25/Tantivy):
  .withSearchIndex("search_content", q => q.search("content", query)
    .eq("domain", site)      // equality filter (Convex supports up to 8)
    .eq("lang", lang)
    .eq("contentType", type))
  .filter(doc => doc.crawledAt > after && doc.crawledAt < before)  // date range post-filter
    │
    ▼
JSON response: { query, results: [...], total, page }
```

## Convex Schema (`convex/schema.ts`)

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  pages: defineTable({
    url:         v.string(),
    domain:      v.string(),
    title:       v.string(),
    content:     v.string(),   // full extracted text (truncated to 8000 chars)
    snippet:     v.string(),   // first 300 chars — shown in results
    lang:        v.string(),   // ISO 639-1: "en", "fr", etc.
    contentType: v.string(),   // "article" | "news" | "docs" | "forum" | "other"
    crawledAt:   v.number(),   // Unix ms timestamp
  })
    .index("by_url",    ["url"])       // for dedup upsert
    .index("by_domain", ["domain"])
    .searchIndex("search_content", {
      searchField:   "content",
      filterFields:  ["domain", "lang", "contentType"],
    }),
});
```

## Advanced Filtering (Search API)

```
GET https://<deployment>.convex.site/search
  ?q=nodejs streams        required: full-text query
  &site=nodejs.org         optional: filter by domain (equality)
  &lang=en                 optional: ISO 639-1 language code (equality)
  &type=docs               optional: article|news|docs|forum|other (equality)
  &after=2024-01-01        optional: crawledAt > date (post-search filter)
  &before=2025-01-01       optional: crawledAt < date (post-search filter)
  &sort=relevance          optional: relevance (default) | date
  &page=1
  &limit=10                optional: max 50
```

**Note on date filters:** Convex search indexes support equality filters only. `after`/`before` are applied as `.filter()` on the search result set (Convex allows this as a chained filter on search queries). Works fine for the expected result volumes.

Response shape:
```json
{
  "query": "nodejs streams",
  "results": [
    {
      "title": "Stream | Node.js Docs",
      "url": "https://nodejs.org/en/docs/...",
      "snippet": "The stream module provides an API for...",
      "domain": "nodejs.org",
      "lang": "en",
      "contentType": "docs",
      "crawledAt": 1712275200000
    }
  ],
  "total": 12,
  "page": 1
}
```

## Content Extractor (`src/extractor.ts` — no external API)

```
fetch(url, { signal: AbortSignal.timeout(8000) })
    │
    ▼
Cap response at 2MB → parse HTML string
    │
    ├── jsdom + Mozilla Readability → clean article text  (primary)
    └── Cheerio body strip (remove script/style/nav/footer) (fallback)
    │
    ▼
franc(text) → lang ("en" | "fr" | ...)  [default "en" if text < 10 words]
classify(url, html) → contentType       [URL pattern + og:type meta]
SHA-256(text) → contentHash             [for dedup: skip if unchanged]
```

## Phase 1 Implementation Order

1. **`npx convex dev`** — create Convex project, generates `convex/_generated/`
2. **`convex/schema.ts`** — pages table + searchIndex (above)
3. **`convex/pages.ts`** — `upsertPage` mutation (insert or patch by URL), `searchPages` query with filters
4. **`convex/http.ts`** — `httpAction` on `GET /search`, parses query params, calls `searchPages`
5. **`src/utils/pLimit.ts`** — custom concurrency limiter
6. **`src/utils/langDetect.ts`** — franc wrapper, ISO 639-1
7. **`src/utils/classify.ts`** — URL pattern + og:type → `article|news|docs|forum|other`
8. **`src/extractor.ts`** — fetch → jsdom+Readability → Cheerio fallback, returns `{ title, content, snippet, lang, contentType }`
9. **`src/crawler.ts`** — Crawlee `CheerioCrawler`, reads `seeds/urls.txt`, calls extractor per page, pushes to Convex via `ConvexHttpClient`, follows same-domain links up to depth
10. **`seeds/urls.txt`** — starter list (nodejs.org, developer.mozilla.org, docs.python.org, etc.)

**Packages:**
```
convex crawlee @mozilla/readability jsdom cheerio franc pino
```
Dev: `typescript @types/node ts-node-dev`

## Phase 2 — JS Sites + Scheduled Re-crawl

11. **`PlaywrightCrawler`** fallback in `src/crawler.ts` — detect SPA (body text < 5% of HTML size, or `__NEXT_DATA__`/`data-reactroot` marker) → re-fetch with headless Chromium
12. **Scheduled re-crawl** — Convex `cronJobs` (free, built-in): re-crawl pages where `crawledAt < (now - 7 days)`, skip if `contentHash` unchanged
13. **Duplicate filtering** — store `contentHash` in Convex; `upsertPage` checks hash before patching
14. **Stats endpoint** — `GET /stats` httpAction returns index size, domain breakdown

## Critical Pitfalls

- **`npx convex dev` must be running** while developing — it watches `convex/` and pushes changes live
- **`ConvexHttpClient` is per-request** (not a singleton) — create a new instance per crawl batch or use `ConvexHttpClient` once for the whole crawler session (single user context is fine for a CLI crawler)
- **Convex free tier storage**: 0.5 GB (~500k avg pages). Upgrade to Starter ($25/mo) for production-scale crawls
- **franc minimum text**: Needs ≥10 words. Default to `"en"` for short pages
- **JSDOM memory**: Cap fetch at 2MB before parsing. JSDOM is memory-hungry on large HTML
